# v0.1.0-alpha.34 — Callers through interfaces and built-in generics

`find_callers` missed calls made through an interface. Two things caused it.
The TypeScript analysis ran without the standard library, so `Record`,
`Promise` and other built-in generics collapsed to `any`; a call such as
`this.handlers[k].verifySignature()` with `handlers: Record<string, Handler>`
was recorded as unresolved. And `find_callers` returned only direct calls, so
an implementation never listed the calls made through the interface member it
satisfies.

The analyzer now reads standard-library declarations (`lib.d.ts` and
`lib.*.d.ts`, chosen from each config's `target` and `lib`) from CodeMemory's
own TypeScript package. They are type information only: library declarations
are never indexed, calls into them stay unresolved as external targets, and no
project file outside the scanned sources is read.

For an instance member, `find_callers` also lists calls whose receiver type is
an interface or base class the member implements or overrides, following the
class's `IMPLEMENTS`/`EXTENDS` ancestors up to depth 10. Those rows carry
`dispatch.via` with the supertype member. The runtime target may be another
implementation, so treat them as possible callers. Constructors, static
members and `super.member()` calls never dispatch and keep their direct
callers only; stored edges still target the supertype member, and
`trace_dependencies` does not add dispatch hops.

A new `scripts/evaluate-project.ts` compares relationship results with the
TypeScript language service and measures tool latency on a selected project.
It reads the published index by default. Its `--unmanaged` mode indexes a
checkout into a disposable `codememory_eval_`/`codememory_test_` database and
refuses any other database.

## Update

On macOS/Linux, run `codememory update --version v0.1.0-alpha.34`. On Windows,
use `codememory.cmd update --version v0.1.0-alpha.34`. Reconnect open MCP
clients after updating. The analyzer version changes, so each registered
project re-analyzes once when its MCP session next starts. No database
migration is required.

## Validation and limits

On macOS, frozen dependency installation, lint, typecheck, build and the CLI
version check passed. All 239 tests across 44 files passed, as did parser
verification, the upgrade acceptance script and a disposable-project
simulation. A new fixture covers interface, union, `Promise`, base-class,
`super`, static, constructor and ES5 cases.

On a 3,188-file TypeScript project, evaluated against the language service
with three seeds of 90 symbols, caller recall moved from 98.3/98.6/100% to
99.7/100/100% and precision stayed at 99.7–100%. Relationship query p95 stayed
within 25–40 ms. A full index took about 58 s, against about 50 s measured
earlier in a separate run. Unresolved references fell only slightly, from
137,625 to 137,352: most remaining targets are external npm packages, and
`@types` and `node_modules` remain out of scope. The tagged Linux, Windows and
macOS release workflow must pass before GitHub publishes this prerelease.
Stable-release acceptance gates remain open.
