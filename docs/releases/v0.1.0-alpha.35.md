# v0.1.0-alpha.35 — Faster indexing, faster queries, safer updates

This release comes from an end-to-end audit tested on two real TypeScript
projects: a 3,193-file ERP (550k edges) and a 5,660-file kiosk application
(1.6M edges). Every performance claim below was measured on those projects on
a disposable database with the managed PostgreSQL 17 container (1 CPU, 1 GiB).

## Indexing

A full index fell from 122 s to 41 s on the ERP and from 640 s to 131 s on the
kiosk project. Most of the time went into writing call edges: the foreign keys
and primary key on `symbol_edges` are gone (migration 11), and publication now
deletes the edges of removed symbols itself, as the former cascade did. Edge
insertion went from 77 s to 11 s and from 440 s to 49 s. Incremental
publication writes only the symbols of files whose analysis changed, and an
unchanged re-run takes 0.4–0.7 s. Parser memory is unchanged (about 2.4 GB and
6.6 GB at peak).

## Queries

Before every tool call, CodeMemory checked for incomplete coverage by reading
each file's stored JSON, which embeds the whole source. That check and the
generated-file flag now read real columns (migrations 10, 12, 13 and 14).
`get_symbol`, `find_callers` and `find_references` dropped from about 22 ms to
3 ms on the ERP and from about 60 ms to 3–4 ms on the kiosk project at p50.
`search_symbols` on the kiosk project went from about 94 ms to 31 ms; a broad
query such as `get` (7,018 candidates) went from 151 ms to 23 ms.

Caller recall against the TypeScript language service is 99.7/100% on the ERP
and 92.3/100% on the kiosk project, with 99.7–100% precision. `find_callers`
no longer lists calls on a sibling subclass as possible callers of an
override.

## Updates and reliability

- `codememory update` and `bootstrap --upgrade` now apply database migrations
  to the managed database after stopping old MCP servers and before switching
  the runtime. A failed migration keeps the previous runtime. An external
  `DATABASE_URL` on an older migration blocks activation until
  `bun scripts/migrate.ts` is run against it.
- Updates stop running MCP servers again; process matching had rejected the
  installer's `--session-projects` flag. Activation rolls back on Ctrl+C or
  SIGTERM, and a stale `update.lock` is recovered.
- Closing a session cancels its index and kills the parser worker. A dropped
  PostgreSQL connection no longer crashes the server. Failing indexes back off
  instead of re-analyzing unchanged input.
- Prisma calls through `class PrismaService extends PrismaClient` are
  detected, namespace imports resolve to the imported file, a checker failure
  in one file no longer aborts the analysis, and files containing a stray NUL
  byte are indexed.
- A `.codememoryignore` that links outside the project now fails the scan
  instead of letting the files it would hide be indexed.

The full list is in the [changelog](https://github.com/iOwsla/integra-codebase-memory/blob/v0.1.0-alpha.35/CHANGELOG.md).

## Update

On macOS/Linux, run `codememory update --version v0.1.0-alpha.35`. On Windows,
use `codememory.cmd update --version v0.1.0-alpha.35`. Reconnect open MCP
clients after updating.

- Migrations 10–14 run during the update. They add columns and indexes, drop
  unused constraints and indexes, and backfill one boolean column; alpha.34
  can still run on the migrated schema.
- The managed PostgreSQL container is recreated with `max_wal_size=4GB`,
  `checkpoint_timeout=15min` and `wal_compression=lz4`. The data volume is
  kept.
- The analyzer version changes, so each registered project re-analyzes once
  when its MCP session next starts.

## Validation and limits

On macOS, frozen dependency installation, lint, typecheck and build passed.
All 360 tests across 65 files passed, as did parser verification, the upgrade
acceptance script and a disposable-project simulation.

- `search_code` for rare terms on a cold, freshly loaded database stays around
  0.3–0.4 s on the kiosk project; its SQL is unchanged from alpha.34.
- The managed PostgreSQL settings gave a small gain (ERP publish 27 s → 25 s,
  kiosk unchanged).
- The receiver-type check for classes is a nominal heuristic under structural
  typing; interface receivers are always kept.
- The tagged Linux, Windows and macOS release workflow must pass before GitHub
  publishes this prerelease. Stable-release acceptance gates remain open.
