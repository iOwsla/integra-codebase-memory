# v0.1.0-alpha.37 — Agent rules start with CodeMemory

In a real session on a 5,660-file project, an agent had every CodeMemory tool
available and never used one: it ran 13 shell commands instead. The installed
rules sat in the middle of a 408-line `CLAUDE.md`. They began with protocol
details and never said which tool replaces `grep`, `cat` or `find`.

The managed block now starts with a short section:

- Load deferred CodeMemory tools with one tool search.
- Call `codebase_status` and `recall_context` first.
- A table of which tool to use for each kind of code question instead of
  `grep`, `cat` or `find`.
- When native tools stay right: file names and globs, configuration,
  non-indexed files, files being edited, and paths with pending changes or
  incomplete coverage.

The detailed protocol follows unchanged. The MCP server's own instructions
carry the same preference.

The installer now keeps the block at the top of `CLAUDE.md` and `AGENTS.md`. On
install or update, a block found further down is moved to the top, and the
project's own lines keep their order below it. A block that is already first is
left unchanged.

## Measured effect

Four headless sessions on the same project asked a lookup question (where an
order quantity is computed and who calls it). They covered old and new guidance,
with tools deferred and with tools preloaded. All four answered correctly with
Grep and Read only, and none called a CodeMemory tool. Preloading every tool
raised the cost of a session from about $0.46 to $2.80 without changing tool
choice, so it is not recommended. Treat this release as clearer guidance, not as
a measured change in agent behavior.

## Update

On macOS/Linux, run `codememory update --version v0.1.0-alpha.37`. On Windows,
use `codememory.cmd update --version v0.1.0-alpha.37`. The update refreshes the
instruction block in every registered project and moves it to the top of
`CLAUDE.md` and `AGENTS.md`. Settings it changes are backed up first. Review the
resulting diff in each project before committing it. Reconnect open MCP clients
after updating. There is no database migration and no re-analysis.

## Validation

On macOS, lint, typecheck and build passed. All 361 tests across 65 files
passed, as did the upgrade acceptance script. Installer tests cover moving an
existing block to the top, preserving user lines and imports below it, and an
unchanged second run.
